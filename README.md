## 仓库内容

- `plugin/`：Chrome Manifest V3 扩展源码
- `hub/`：商品接收入库、定向传输、在线与认领目录服务源码
- `worker/`：本机紫鸟工人，用于核验目标店页面身份与插件状态
- `hub/public/downloads/temu-transfer-plugin-11.0.4.crx`：当前已签名插件

- `docs/release-v55.md`：本次网站调整、验证与限制

- 根目录的 `temu-shop-transfer-10.10.47.crx` 是历史文件，不是当前版本

## 安装插件

下载 [11.0.4 CRX](hub/public/downloads/temu-transfer-plugin-11.0.4.crx) 或 [11.0.4 ZIP](hub/public/downloads/temu-transfer-plugin-11.0.4.zip)。在 Chrome 或 Edge 的扩展管理页面开启“开发者模式”，将 CRX 文件拖入页面；浏览器不允许直接安装时，解压 ZIP 并选择“加载已解压的扩展程序”。安装后刷新店铺商品列表页，旧插件不能作为拆分任务的投递目标。

## 运行中转仓

建议使用 Node.js 22 或更高版本。默认本地调试地址为 `http://127.0.0.1:18380`；生产商品库存使用 MySQL 8.x，资源准入读取 Linux 服务 cgroup 限额。

```powershell
cd hub
npm ci
npm start
```

开发环境也可以将 `plugin/` 作为未打包扩展加载，便于查看实时修改。

数据库、凭证及数据目录由部署环境单独配置；不要直接在有在途传输的生产库运行迁移。当前正常传输不依赖旧账户执行器，历史调度和部署脚本不代表当前版本的启动方式。详见 [v55 发布说明](docs/release-v55.md)。

插件的 `direct-adapter.js` 是 `worker/direct-create-prepare.js` 的构建产物；来源保真使用独立模块。
修改转换源文件后需在 `plugin/` 目录执行 `node build-direct-adapter.mjs` 重新生成，不要直接改产物。

## 校验

```powershell
cd hub
npm run verify
```

默认回归覆盖接收入库、一次性传输、插件执行、仅错误通知、标红过滤、详情布局、用户隔离和管理员登录。真实数据库专项需要隔离测试 MySQL，不应使用生产库；历史账户调度专项不作为当前收发流程的验收依据。

## 判定责任边界

- **能否创建由目标店平台判定**：插件不再用本地规则预判“目标店要哪些必填项”。本地模板规则一旦比平台严，就会造出平台上并不存在的失败，因此缺少必填项等只记为备注，由平台返回的错误作为真实原因。
- **传输完整性不等于固定商品模板校验**：核对来源数据的传输及身份，不把所有商品强行套入同一结构。
- **收发与执行分开**：服务器收存来源商品和资质，只传递人工选定的任务，不保存目标店执行进度或等待成功确认。目标插件判断重复、资质匹配、暂停、结束及平台结果；仅符合商品全局错误分类的通知回传货号和原因，供商品库标红和禁传。店铺专属的资质错误只在插件显示。
- **商品与资质分开**：商品任务重复即跳过，不自动补资质；资质任务只匹配未删除商品，货号或SKU不一致显示“没有匹配到内容”，不创建商品、不主动替换已提交或被驳回的资质。
- **单次人工点击的重复传输与重新提交分开处理**：同次投递应避免重复接收；人工重新点击产生新操作。平台结果未知不能当作明确未提交后自动重投。
- **标红可人工解除**：商品库支持按标红状态筛选，也可对选中的标红商品执行“解除标红”。

## 数据与凭据

本次同步不包含服务器凭证、插件令牌、私钥、运行日志或生产数据库。原仓库已有 `hub/fixtures/` 测试样本，本次未新增或替换这些样本。运行产生的 `hub/data/`、`plugin-tokens.json`、证书和本地环境配置均应留在部署环境，禁止提交。

## 已知问题

实时选择读取与采集批次已分离，但批量发现仍依赖页面及已见数据，不宣称突破任意规模虚拟列表的读取上限。资质支持范围和附件限制见 [插件说明](plugin/README.md)。真实店铺商品创建及资质提交须联合测试，平台接收不等于审核通过；平台最后读取与写入之间的并发行为不能仅靠插件保证，因此不要同期手工修改同一资质。详见 [发布说明](docs/release-v54.md)。
