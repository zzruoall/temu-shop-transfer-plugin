# 店铺中转插件

这是云仓直连验证版 `10.10.42`，旧采集插件仍在 `../legacy-v1/extension`。

本版修复 `/temu/api/ingest` 对应测试连接、心跳、任务领取和回传的子目录路径。云仓设置使用完整入库地址及设备令牌（不是管理员登录密码），先测试连接再采集上传。商品创建仍由连接器执行，尚未迁入插件；未映射店铺也仍需核验，不根据名称猜测商城ID。

发布 10.9.0 后刷新两个店铺的卖家中心页面；优先原位更新同一扩展，不要清除已有数据和配置。若曾并装另一套旧插件，请禁用另一套，不能并存采集。

加载目录：`E:\project\ziniao\plugin`

默认中转仓地址：`http://127.0.0.1:18380/api/ingest`

插件保留采集、上传和日志导出。进入 agentseller.temu.com 的商品列表后点击采集，先统计当前页SPU，再复用网页正常客户端逐个查询 product/query，间隔800毫秒，不打开编辑页。每件详情经过商品ID校验并落库后才计数；权限错误、超时或页面切换会停止，失败原因写入日志。普通采集不再刷新页面，切到目标分页后点击采集即可只读取该页；刷新仍不会继续旧队列，需重新点击采集。暂不自动翻页、不使用硬编码网页模块号、不构造登录凭证。

## 10.10.42 商品货号与 SKU 货号分层判重

此前判重把 `productSkcList[].extCode` 和 `productSkuList[].extCode` 拍平成一个集合，导致商品本身有货号时也可能拿 SKU 货号去命中目标店其他商品；反过来，目标店 SKU 货号也可能被误用于商品级匹配。本版把两级货号分开：

- 商品/SKC 货号只读列表行 `extCode/skcExtCode` 或 `productSkcList[].extCode`，同时保留为商品库“货号”展示字段。
- SKU 货号只读 `productSkuList[].extCode`（及列表接口的 SKU 摘要字段），只在商品完全没有商品/SKC 货号时用于判重。
- 目标店判重、批次内保留、提交请求完整性和提交后回查全部使用同一规则，不再前后不一致。
- 商品级服务端过滤字段不是当前 Temu 的稳定契约，过滤返回 0 条也不会直接判定不存在；未命中时继续完整分页，只有完整扫描结束才认为目标店无同款。

## 10.10.41 列表属性与香水分档补齐

部分商品的 `product/query` 详情没有把列表接口已有的属性写进编辑结构，例如 `香味`、`香精浓度`；旧任务快照又只保留了名称和值。本版在采集入库时保留列表属性的模板编号，并在目标店预检前把历史摘要属性合并回来源商品，避免同一资料在详情和列表之间来回丢失。

香水分档提交前会按目标模板校正已存在属性，并只补来源能证明的字段：列表明确给出 `香味=玫瑰` 时补“玫瑰”，SKU 明确为 `15ml` 时映射到目标“≤100ml”，来源 `香精浓度3-5%` 映射到覆盖该范围的目标档 `香精浓度1-5%`。商品级 `cosmeticInfoVO` 会在 SKU 级为空时按原成分编号下传到每个 SKU。没有明确来源值的必填项仍会阻断，不根据标题或常识猜值；例如来源接口没有“留香时长”的小时数时，任务会明确报缺少该字段，而不是静默提交错误声明。页面预检抛出的业务原因会原样回传到工作日志；网页人工重试则以服务器递增的重试序号作废旧本地 attempt，避免上一轮 `done` 标记把重新排队的商品跳过。

## 10.10.40 分页采集不再刷新丢页

此前“采集当前页”会先刷新卖家中心页面。Temu 的商品分页保持在页面内存中，刷新后通常回到第一页，因此运营在“未发布第二页”点击采集时，实际采集并上传的是刷新后的第一页。本版改为直接读取点击时的当前 DOM 商品行，再从当前页 SPU 开始详情补采；不再为了重新触发列表接口而刷新页面。

同一页重新采集时也会清除上一批次留在页面内的详情终态和跨页累积 SPU，确保新批次只包含点击时当前页可核验的商品。平台切页后仍需分别点击一次“采集当前页”，插件不会自动翻页。

基础资料、图片、SKU和规格分别核验，正文为空不自动判定漏采。完成后发起本批次完整包下载，请在浏览器下载列表确认；网站可手动上传文件。插件“上传”发送采集批次；网站“接口创建”属于独立的目标店操作，须确认合规并通过目标店预检，不把采集完成当成发布资格。

若需要定位“列表页没有详情/图片”的原因，在插件工具区展开“备用导出与高级诊断”，点击“开始接口诊断”，然后刷新列表或打开一次商品并操作相关区域，最后点击“停止并导出接口诊断”。诊断页只导出脱敏后的接口路径、状态、字段树、ID 路径和图片/规格/正文证据，不会开启普通采集，也不会保存响应正文。

## 10.10.39 店铺已删除商品不再上传

插件采集商品列表时读取行内的实时删除标记：商品行 `removeStatus` 为 1 表示该商品已经在店铺里删除（平台随后按 `autoDeleteRemainingDays` 自动清理），为 0 表示仍在店铺内。这些商品不再补详情、不计入当前页采集数量、也不会进入入库白名单；即使运营手工勾选过，同样不会上传。

判据必须用商品行的实时状态，不能用货号历史：同一货号被删除后可能重新建成新商品，新商品的 productId 不同、状态也是在店，用货号拉黑会误伤重建后的商品。对应地，“在店”状态会即时解除同一 SPU 的删除标记，页面删除后又恢复时不会漏采。

插件先读取当前页每行可见的 SPU ID 和 SKC ID，再复用网页正常客户端调用 `/visage-agent-seller/product/skc/pageQuery`，通过 `productSkcIds` 只取当前页商品的明确 `removeStatus`；不按货号查整店，也不会浏览其他页。主列表响应若已在同一行同时提供商品 ID 和 `removeStatus`，只在当前页主列表接口内提前采用；其他商品接口即使出现同名字段也不参与判断。

当前页有采集目标但 SKC 缺失、接口少返回商品或状态为 `null`/未知值时，本轮停在“待人工确认”且不上传，绝不把无法核验的商品当成在店商品。当前页商品全部是已删除时，面板显示“当前页商品均为店铺已删除（不上传）”并直接结束，不报成采集失败。展开“采集统计详情”可看到本次跳过的数量，宿主属性同步 `data-removed-count` 供紫鸟 CLI 读取。

## 10.10.37 回查不再比对商品ID

商品ID由平台在创建时随机生成，同一件商品在不同店铺的ID必然不同，它只在单个店铺内部有意义。此前回查把“查询接口返回的ID”和“提交时拿到的ID”当作是否同一件商品的依据，这个比对没有判断价值，只会把已经创建成功的商品误判成“回查不匹配”。本版删除这处ID比对，插件与本地连接器两条创建路径同步去掉。

回查改为只按设置好的内容确认：商品名称，以及内容完整性检查（SKU 数量与货号规格对应关系、主图数量、SKU 价格、缩略图、净含量、成分）。同时补上“回查没有返回商品”这一显式判断，空结果不会被当成通过。新增/查询接口返回的商品ID仍会记录并回传给云仓，作为运营核对目标商品的线索，只是不再参与判断。

仍保留两处同店ID校验，它们比对的是同一个店铺内部的ID，与本版删除的跨店比对不是一回事，删除反而会丢掉真实的数据错位保护：一是来源快照的商品ID必须与任务SPU一致（否则说明取到的是别的商品资料），二是采集时详情接口返回的商品ID必须与当前采集的SPU一致。跨店铺的判重自始至终只认货号。

## 10.10.36 回查失败不再误报结果未知

提交成功后 Temu 会刷新商品列表页，详情回查（`product/query`）可能正好落在文档重载或路由切换的瞬间，注入脚本拿不到结果。此前这种情况下插件会直接报“结果未知”，而商品其实已经创建成功，运营必须手动刷新页面才能看到——这是本次真正修掉的缺陷。

回查失败后原本有一条“按新商品 ID 到目标店列表确认”的兜底，但代码里那个用于比对的商品 ID 只赋值、从未参与匹配，而且没有货号时函数会直接返回“结果未知”，所以这条兜底永远走不通，等于不存在。本版删掉这段失效分支，改成按提交时同一批货号回列表确认：这批货号在提交前刚刚确认过不存在，现在能查到就说明本次创建已经落到目标店。列表查不到、分页不完整或商品没有货号，仍保持“结果未知”，绝不当成成功。

回查与兜底确认共用一个有限时间窗（约 20 秒，最多 12 轮），窗口内重试以覆盖页面刷新；两者都用尽才停下并上报结果未知。整个回查阶段都是只读接口（`product/query` 与列表 `pageQuery`），任何情况下都不会因为回查失败而重发新增请求。

同时清理了判重路径上遗留的失效字段：页面侧只保留货号作为判重主键，商品名称、来源 SPU/SKU 内部 ID 不再进入匹配逻辑，避免后续维护者误以为名称也参与判重。注入拿不到结果时的错误文案也写明了原因（可能正在刷新或已离开商品列表页），便于在操作日志里和“平台拒绝”区分开。

回查本身确实要比内容，比较项是：商品 ID、商品名称，以及 SKU 数量、主图数量、货号与规格的对应关系、SKU 价格、SKU 图片、净含量、成分。目标店页面上的“备货区域”等表单字段不在这份比较里，它只影响生成请求时是否补齐字段，不影响回查结论。为避免把“页面重载没读到”和“内容比对不通过”混为一谈，按货号确认成功时会把回查失败的真实原因原样写进结论，运营在工作日志里能直接看到是哪一项没过。

## 10.10.34 结果未知不再自动重发

接口创建只允许按货号判重，平台回查返回的 productId 是每次新增随机生成的，不能当作判重依据。本版收紧判重主键：商品/SKC 货号存在时只比较目标店行级商品货号；商品货号为空时才使用 SKU 货号。服务端过滤不可用、页面版本不兼容、分页重复或超过分页上限都判为“结果未知”，禁止在无法证明不存在时创建。商品没有任一层货号时直接判“结果未知”，不用名称、SPU 或 SKU 内部 ID 猜测同款。

回查拿不到明确结果时不再心跳续传或重新提交。此前“结果未知”会被自动复核并再次提交，同一 SPU 因此产生过两次创建请求和重复商品；本版把 unknown 状态隔离：刷新页面、切页、重开浏览器都不会自动把它送回创建队列，面板显示“结果未知”，只有人工点“人工确认后重试”才重新排队。重试排到上传队伍最后一位，且必须先清除旧 attempt 的授权键、请求指纹和商城标识，确保不会复用上一次的提交许可。

服务器侧同步收窄职责：网站只做接收、存储、下发，不读取紫鸟/Temu 页面内容判断平台商品是否重复，也不解读插件上报的平台返回值；同店同货号的重复判断完全交给目标店插件，服务器只维护站内商品库（店铺 + SPU + SKU 指纹）。发送侧唯一的约束是目标店插件此刻仍在提交（creating）时拒绝下发，避免同店并发写入；新任务落库时会撤销旧任务里重叠的未完成项，避免同一货号在队列里堆积多份。新增 `POST /api/jobs/direct-retry` 作为人工重试的落库入口，插件在重新排队前先调用它，旧 attempt 留痕后任务回到队尾，由插件重新做货号复核。

预检阶段同店并行上限 3 个，提交阶段同店严格串行，避免页面被连续操作挤占导致提交失败。

## 10.10.33 停止接口创建

面板的“接口创建进度”里新增“停止接口创建”按钮。此前批次一旦启动就只能靠刷新页面打断，而刷新会让页面重新领取任务继续上传，运营没有任何可靠的刹车。本版把停止标记按目标店铺落盘到扩展存储：停止后无论刷新页面、切页还是重开浏览器都不会自动继续，必须在面板上点“继续接口创建”才恢复；停止时按钮改文案、进度块转橙色，标题栏同时显示“已停止接口创建”，收起工具区也看得到。

停止是协作式的。插件只在两个安全点收手：开始下一件商品之前，以及为下一件商品申请创建授权之前。已经发出、平台已受理的新增请求无法撤回，此时仍会把这件商品的结果回查完并写入日志，停止说明里会写明“已发出的提交无法撤回”。停止只作用于当前店铺，其他目标店的自动创建不受影响。

按钮只在当前店铺确实存在接口创建任务或已处于停止状态时出现，避免普通采集店铺看到无效入口。

## 10.10.31 面板壳层

标题栏可整条拖动，松手后自动停靠到更近的左右边侧。标题栏右侧两个按钮职责分开：“展开”只负责显示工具区（采集统计、导出操作日志、上传采集包、接口任务自动创建、连接设置等），“收起”只收回工具区，采集进度和“是否完成”始终留在主面板；“—”把整个面板收缩成贴边小球，小球只保留一个 ‹/› 箭头，点击小球还原收缩前的状态。按钮文案必须跟随真实状态，不能再出现“点展开却把面板缩成小球”的误导。

## 10.10.32 目标店必备字段

备货区域（一般仓库/保税仓库）与生产地由目标店配置决定，来源店同款商品可能是空值。本版在生成新增请求时按目标店要求补齐：备货区域优先沿用来源商品值，来源为空而目标店要求时按该店既有做法提交一般仓库（1），保税仓库为 3、不可互相替代；生产地按产地国补入并去重。补齐动作写入操作日志的准备阶段说明，运营能看到实际提交了什么。此前这类商品会被平台以“Stocking Area Cannot Be Empty（1000003）”整单拒绝，且日志看不出是店级必填字段导致。

“该店是否要求备货区域”只有在配置查询带产地国时才有答案；若这次查询失败，不能当成“该店不要求”静默放过，本版会把失败原因写进准备阶段日志，运营可据此区分是店级必填校验还是平台偶发拒绝。

## 10.5.1 操作诊断

删除面板的“清空商品数据”和重复的“刷新入库状态”；状态仍自动刷新。常用区保留采集、上传采集包、打开目标上传页、导出操作日志和连接设置。任务资料导出/上传确认仅在相应任务存在时显示；统计和备用诊断折叠。

操作日志默认记录，无需开启接口诊断。内容包括页面进入/离开、按钮点击、面板状态变化、业务命令开始/结果、连接HTTP状态/耗时、任务身份/领取/回传和本扩展下载状态，附导出时配置是否有令牌、权限判断和本地任务摘要。既有采集日志一起导出为 `temu-operation-logs-*.json`。HTTP成功仅表示收到响应头，业务命令成功才表示该操作完成。

操作日志保留最近1500条且不超过1MiB，裁剪数量随文件导出；local写入失败时至多50条备用证据存session，可跨后台工作线程重启但不跨浏览器退出。两个存储区同时失败或离页/崩溃瞬间在途消息仍可能丢失；文件会尽量报告当前可见错误，不承诺无限或完整历史。日志不采集令牌、Cookie和完整商品正文，但包含商品ID、页面路径及原有采集诊断摘要，仍按业务资料保管。

网站通过 CLI 向10.9插件定向投递。商品库选择目标店并点击“接口创建”，明确确认合规声明后，本机连接器在目标店列表页生成请求并调用新增接口，不打开表单。插件负责接收和展示日志；新增请求由本机连接器通过紫鸟CLI执行，必须同时运行本地网站、连接器和目标店列表页。旧任务仍保持手动流程，不会升级后自动创建。

回查会核对新SPU、名称、SKC/SKU数、主图数、价格、净含量和成分。结果不明保留一次性占位和新SPU（若已有），禁止取消后重发；请先查看网站工作日志和 test-artifacts/direct-results 中回执，再核对平台。创建不代表站点已上架。当前仅女式剃毛乳液单品实测成功，其他类目仍需小批验证；半托管、不唯一SKU匹配、模板变化或字段丢失会停止，不猜测补值。平台模块更新需要重新适配。
