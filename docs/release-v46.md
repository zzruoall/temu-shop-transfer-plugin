# 网站 v46 与插件 10.10.75

## 发布范围

2026-10-07 同步当前线上网站 v46、插件 10.10.75 源码及原始 CRX/ZIP 安装包。网站和插件来自线上发布目录，只读导出后逐文件核对 SHA-256；本机 worker 构建源码来自当前本地目录，单独记录摘要。没有在同步过程中重建或改写已发布插件包，也没有修改或重启生产服务。

网站本轮版本修复普通用户访问管理站时无法重新登录的问题：`/temu/admin` 转到 `/temu/admin/login`，普通身份仍无法读取管理 API。管理员登录成功沿用原共享会话切换浏览器身份，并非同时保留两套独立登录。

## 当前职责

- 服务器接收商品入库、定向传输，保留商品库、在线状态、店铺认领和绑定目录。
- 正常传输不依赖历史账户业务执行器，不等待插件成功确认，也不保留旧发送任务自动重放。
- 插件独立进行目标店判重、上传、暂停和结束；正常成功及进度不回传，只有错误商品回传货号和原因。
- 商品错误标记按来源实例处理并去重；标红商品会被后续发送过滤，商品删除重传不会继承旧实例错误。
- 商品库支持错误原因展示、局部状态自动更新与人工解除标红。服务端资源准入仍有边界，不代表服务器控制目标插件的运行速度。

仓库保留的旧账户调度、迁移及历史部署脚本用于追溯，不应直接作为 v46 的部署指令。数据与凭证必须由部署环境另行配置，生产迁移及清除操作不能从测试脚本推导。

## 已知未修复问题

以下属于 10.10.75 的已确认问题，此次上传不是修复版本：

1. 大列表只挂载屏幕附近的商品行；采集范围发现仍依赖 DOM，人工快速滚动可能漏识别，不能把面板已发现数量当成完整分类总量。
2. 实际商品页采用 Beast `TAB_active...`，已有页签选择器不能完整识别分类；同一 URL 下的旧商品和勾选集合可能影响统计。
3. 删除状态桥每次最多查询前 200 个 SKC，超出部分缺少核验结果；这个限制不等于面板只能识别 200 件商品，也不是服务器资源不足的证据。

修复方向是使用当前筛选对应的完整列表结果、隔离分类集合、分批核验删除状态。尚未实施，不能据此宣称采集 220 件已通过完整验收。
